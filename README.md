# Vite native config codemod

> [!NOTE]
> This was generated by LLM and I only　skimmed through the code. While I guess it would work for most cases, there might be edge cases that this does not cover.

Vite's native config loader follows the runtime's ESM rules. This codemod makes the imports reported by Vite's compatibility warning explicit:

- relative file imports gain their real extension;
- directory imports point to the concrete `index` file;
- named JSON imports become a default import followed by destructuring.

Install the codemod's dependencies:

```sh
pnpm install
```

Then pipe a build log containing Vite's compatibility warning into the codemod. For example, from a sibling Rolldown checkout:

```sh
pnpm docs:build 2>&1 | node ../vite-native-config-migration-codemod/index.mjs --root docs
```

The paths in a Vite warning are relative to Vite's root. The root defaults to the current working directory; pass `--root` when Vite runs with a different root:

```sh
pnpm --dir path/to/project exec vite build 2>&1 | node path/to/vite-native-config-migration-codemod/index.mjs --root path/to/project
```

The warning block is the source of truth: only reported files and specifiers are considered. The driver uses `@ast-grep/napi` to select their import/export AST nodes in-process, then resolves relative paths on disk before editing. It stops instead of guessing when a specifier is missing or resolves to more than one supported JavaScript or TypeScript file.

Run the tests with `pnpm test`.
